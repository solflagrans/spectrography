# Интерпретатор спектра

## Назначение приложения

Приложение — рабочее пространство для интерпретации спектральных данных. Пользователь загружает измерение, проверяет качество исходных данных, подготавливает спектр, находит и проверяет пики, сопоставляет их со спектральными линиями и формирует объяснимое заключение.

Основные продуктовые принципы:

- исходные измерения не изменяются незаметно;
- каждое заключение прослеживается до конкретных пиков и линий справочной библиотеки;
- автоматическое определение является проверяемой гипотезой, а не безусловным результатом;
- отрицательный или неопределённый результат считается полноценным;
- параметры, преобразования, версия библиотеки и пользовательские решения должны сохраняться для воспроизводимости анализа;
- числовая оценка совпадений является эвристикой ранжирования, а не статистически калиброванной вероятностью.
- тип спектра ограничивает только физически допустимые методы интерпретации и никогда не задаёт ожидаемый химический состав.

## Технический стек

Основной стек:

- Next.js 16 с App Router;
- React 19;
- TypeScript 6 в строгом режиме;
- CSS Modules и CSS custom properties для интерфейса и дизайн-токенов;
- pnpm 11;
- Vitest для модульных тестов;
- IndexedDB для данных локальной рабочей сессии;
- `localStorage` только для идентификатора активной сессии;
- Vercel как целевая среда публикации.
- Zustand для состояния интерактивного редактора текущей сессии;
- Apache ECharts с модульными импортами для визуализации спектра;
- Lucide React как единый набор интерфейсных иконок;
- Radix Primitives, подключаемые отдельными пакетами, для доступных диалогов, popover, tooltip, tabs и других интерактивных паттернов;
- `clsx` для условной композиции классов CSS Modules;
- Zod для runtime-валидации импортируемых данных, сохранённых сессий и границ будущего API;
- SheetJS CE для чтения XLSX-файлов в браузере;
- TanStack Table для сортировки, фильтрации, выбора и представления таблиц пиков и спектральных линий;
- React Testing Library для тестирования компонентов;
- Playwright для сквозных пользовательских сценариев.
- `tsx` для запуска локальных TypeScript-генераторов данных в разработке.
- AGENTS.md необходимо обновлять при изменении архитектуры, существующих продуктовых решений или технического стека.

Предполагаемые зависимости добавляются только вместе с функциональностью, которая их использует. Radix Primitives подключается по отдельным компонентным пакетам, а ECharts — через модульные импорты, чтобы не включать в клиентский bundle неиспользуемый код.

## Архитектура

Код разделён на слои:

- `src/app` — маршруты Next.js, layout и композиция страниц;
- `src/features` — вертикальные пользовательские сценарии и их UI;
- `src/application` — операции импорта, экспорта и координация предметных сценариев;
- `src/domain` — предметные модели, алгоритмы анализа и контракты хранилищ;
- `src/infrastructure` — адаптеры IndexedDB, браузерных API и будущих внешних сервисов;
- `src/fixtures` — демонстрационные и тестовые спектры.

Направление зависимостей идёт от интерфейса и инфраструктуры к предметному ядру. `src/domain` не зависит от React, DOM, Next.js, Vercel или конкретного хранилища. Алгоритмы анализа остаются чистыми функциями, чтобы их можно было выполнять в браузере, Web Worker, серверном маршруте или отдельном пакете.

JSON-, XLSX- и AvaSoft RAW8-парсеры находятся на границе `src/application/import-spectrum`: они валидируют внешние данные до передачи в предметное ядро. RAW8 разбирается локально из `ArrayBuffer` через `DataView`; массивы `dark` и `reference` сохраняются как вспомогательные исходные данные и не применяются автоматически. Исходный порядок точек хранится без изменений; сортируется только отдельная подготовленная копия, и сортировка фиксируется как выполненная операция.

UI-состояние и сохранённая рабочая сессия — разные уровни. Zustand предназначен для временного состояния редактора, а данные сессии сохраняются через `AnalysisSessionRepository`. Текущий браузерный адаптер использует IndexedDB; серверное хранилище в будущем должно реализовать тот же контракт. Видимость слоёв спектрального графика и текущий диапазон масштабирования относятся только к представлению: они не входят в предметную модель, не запускают пересчёт и не сохраняются в рабочей сессии. В разделе «Данные» график всегда показывает только неизменённый исходный спектр; переключатели слоёв доступны в аналитических разделах. Диапазон масштабирования сохраняется при обновлении результата одного анализа и сбрасывается при смене источника данных.

Рабочая сессия схемы 3 хранит расширяемый тип спектра и параметры коррекции шкалы длины волны. Новые анализы и сессии создаются с `plasma-emission`. Значение `unspecified` остаётся только внутренним legacy-значением для чтения старых данных, не создаётся заново и не показывается в интерфейсе; при загрузке оно, как и отсутствующий тип старой схемы, нормализуется в `plasma-emission` без изменения исходных измерений. Селектор типа остаётся видимым в разделе «Данные» и содержит один вариант «Эмиссия плазмы/разряда», сохраняя возможность расширения списка. Тип не влияет на ожидаемые элементы и разрешает только физически применимые предметные методы. Молекулярный анализ N₂/N₂⁺ для новых анализов выполняется автоматически.

Анонимная сессия изолирована на уровне origin и браузерного профиля. Без аутентификации один общий профиль означает одно общее локальное хранилище. Синхронизация между устройствами и строгая персональная изоляция потребуют аутентификации и серверного хранилища.

Встроенная библиотека спектральных линий формируется из ограниченной официальной TSV-выгрузки NIST ASD 5.12. Исходные выгрузки и параметры выборки находятся в `data/nist-asd`, чистые парсер и нормализатор — в `src/application/spectral-library`, детерминированный генератор — в `scripts/build-spectral-library.ts`, готовый версионированный файл — в `src/domain/spectral-library/generated`. Приложение и production-сборка не обращаются к NIST по сети. Команды `pnpm library:build` и `pnpm library:check` соответственно обновляют и проверяют локальный результат.

Молекулярная библиотека является отдельным локальным набором и не смешивается с атомными линиями. Первая версия содержит N₂ C³Πᵤ→B³Πg и N₂⁺ B²Σᵤ⁺→X²Σg⁺ из Moose/MassiveOES. Исходная версия, лицензия MIT, публикации, SHA-256 оригинальных баз и ограниченной выгрузки зафиксированы в `data/molecular-spectra`; импорт и генерация выполняются скриптами `scripts/import-moose-molecular-source.ts` и `scripts/build-molecular-library.ts`, готовый файл находится в `src/domain/molecular-spectrum/generated`. Production не обращается к внешнему источнику.

Каждая справочная линия является отдельной предметной сущностью со стабильным идентификатором, элементом, степенью ионизации, наблюдаемой и Ritz-длиной волны, явно выбранной предпочтительной длиной и средой, исходной относительной интенсивностью, доступными характеристиками перехода, ссылками и версией источника. Наблюдаемая длина предпочтительна; Ritz используется только при её отсутствии. Отсутствующие характеристики не заполняются предположениями. Манифест фиксирует источник, версию NIST, DOI, дату получения, параметры выборки, число строк и SHA-256 нормализованных записей. Завершённый анализ хранит использованную версию библиотеки, параметры, исходный набор данных и результат.

Единый предметный конвейер принимает один или несколько спектрометрических каналов. Каждый канал имеет стабильный идентификатор, собственные исходные данные, параметры, диапазон, кривые базовой линии, локального шума и порога, подготовленный спектр, пики и воспроизводимую FWHM-оценку фактического разрешения. Если один импортированный массив содержит разрывы шкалы или длинные повторяющиеся минимумы-маски, рабочая копия автоматически разделяется на непрерывные детекторные диапазоны; маски не считаются измеренным нулевым сигналом, а загруженный исходный массив не изменяется. Разные файлы не объединяются автоматически. Подготовка и поиск пиков независимы по каналам, гипотезы строятся по совокупности каналов.

Подготовка использует один воспроизводимый метод: сглаживание Савицкого—Голея, робастную кривую базовой линии AsLS на фактической сетке длин волн, локальный MAD первых разностей остаточного сигнала и выбранную нормализацию. Пик хранит канал, исходный индекс, измеренную и уточнённую координаты, неопределённость положения, исходную и подготовленную интенсивность, выраженность, SNR и физическую ширину. Качественные пики уточняются квадратичным локальным профилем только в подготовленной копии. Поиск учитывает минимальный SNR, выраженность, диапазон ширины и расстояние. Локальный порог является кривой. Алгоритмы и обоснование параметров документированы в `docs/analysis-pipeline.md` и `docs/identification-quality-profile.md`.

Молекулярные системы сопоставляются с формой нескольких характерных участков, а не с набором локальных максимумов. Эталон переносится на фактическую сетку и сворачивается до оценённого разрешения канала; подбор использует локальную базовую линию, шум и одно малое общее смещение длины волны. Одиночный участок, отсутствие ключевого участка или результат, не отделившийся от смещённых отрицательных контролей, отклоняется. Числовое качество формы — только эвристика ранжирования и не интерпретируется как вероятность, концентрация или температура плазмы.

Атомные N, молекулярные N₂ и N₂⁺ остаются разными гипотезами и объединяются только в пользовательском объяснении элемента «Азот». Пики, перекрывающиеся с молекулярной полосой, сохраняются в модели, но атомные и молекулярные индексы не складываются: один участок сигнала не учитывается дважды как независимое доказательство.

Фиксированный допуск сопоставления не используется. Каждый кандидат получает адаптивный допуск из шага сетки, оценённого разрешения, ширины и SNR пика, неопределённости уточнения положения, доступной неопределённости справочной линии и неопределённости калибровки. Все компоненты сохраняются в результате. Минимальное расстояние поиска пиков ограничивается локальным шагом сетки, поэтому один числовой параметр не подавляет разрешаемые УФ-линии. Для идентификации соседние линии одного элемента и степени ионизации объединяются в спектральные группы по лучшему доступному разрешению пригодных каналов; один низкоразрешающий канал не скрывает разделение, которое реально наблюдается другим. Гипотезы используют точное взаимно-однозначное сопоставление пиков и групп внутри элемента и канала с явной возможностью оставить слабое пограничное совпадение неназначенным. Неразрешимый мультиплет является одним независимым свидетельством, но все его линии и наблюдения сохраняются для прослеживаемости и многоканальной поддержки.

До идентификации канал оценивается по диапазону, шуму и полезному динамическому диапазону, дрейфу базовой линии, выбросам, повторению предельных значений, количеству признаков, надёжности разрешения и калибровки. Результат пригодности принимает только три словесных уровня; без известной разрядности повторение предельного значения не называется насыщением. Автоматическая коррекция допускает лишь общее смещение при нескольких сильных однозначных опорах, разнесённых по диапазону, и обязана улучшить независимую проверочную часть. Она применяется только к подготовленным копиям, сохраняет метод, величину, неопределённость и опоры и может быть отключена. Все константы собраны в версионированном профиле `src/domain/spectrum/quality-profile.ts`.

Характерные признаки выбираются отдельно для элемента и степени ионизации после группировки по разрешению: только покрываемые наблюдаемые линии с числовой однозначной относительной интенсивностью, до десяти наиболее интенсивных спектральных групп. Соседние члены найденного мультиплета не считаются отсутствующими. Относительная интенсивность сравнивается только внутри элемента и степени ионизации и не является вероятностью. Качество наблюдения учитывает SNR, выраженность, ширину, отклонение, многоканальную поддержку и неоднозначность пика; числовые индексы являются эвристиками порядка, не вероятностями. Атомная гипотеза обязана иметь не менее трёх качественных групп, ключевой и достаточно специфичный признак, согласованное общее смещение внутри каналов и превзойти все детерминированные циклически смещённые контроли; очень точное многолинейное созвездие может пройти консервативный контроль при четырёх специфичных группах либо при трёх полностью специфичных группах с сильным признаком, хотя бы одной ключевой группе и малой доле равноценных контролей. Отклонённая гипотеза никогда автоматически не переносится в основной список. Слабые, нехарактерные, единичные, неоднозначные и не отделившиеся от контролей гипотезы хранятся с причинами. Идентификатор пика привязан к каналу и позиции точки в неизменённом исходном наборе, в том числе после автоматического выделения рабочих детекторных диапазонов, поэтому UI может сохранять выбор при пересчёте, пока эта точка остаётся пиком. Выбранный пик и открытый подраздел панели относятся только к состоянию интерфейса, не входят в предметный результат и не сохраняются в рабочей сессии; при смене источника выбор всегда сбрасывается.

Верхнеуровневая навигация состоит из разделов «Данные», «Обработка», «Анализ» и «Библиотека». Основной путь — загрузить или заменить измерение в «Данных», дождаться автоматического пересчёта, открыть краткий вывод в «Анализе» и при необходимости раскрыть доказательства. Видимый селектор физического типа не добавляет обязательного шага перед импортом. Отдельного запуска подготовки, поиска пиков и идентификации нет: после загрузки и изменения значимых параметров единый конвейер пересчитывается автоматически. Во время пересчёта предыдущий результат остаётся резервным валидным состоянием, но визуально скрывается и не выдаётся за актуальный. «Библиотека» является самостоятельным справочным разделом; незавершённого раздела результата и экспорта в основной навигации нет.

Раздел «Анализ» объединяет состав, пики и доказательства. Режим «Состав» является основным и использует master–detail-композицию: слева на широких экранах представлены только принятые атомные и молекулярные гипотезы, а слабые и неоднозначные альтернативы находятся в раскрываемых технических подробностях; на небольших экранах боковая панель скрывается, а выбор состава остаётся доступен в карточке краткого вывода. Режим «Все пики» является дополнительным. Справа сначала показываются осторожное заключение, влияние качества измерения, короткое объяснение и только качественные характерные группы или области молекулярных полос. Отсутствующие признаки, все назначения, оценка случайных совпадений, допуски, калибровка и другие диагностические показатели раскрываются отдельно. Выбранная гипотеза, канал, пик и режим анализа являются только UI-состоянием: выбор сохраняется при пересчёте, пока сущность существует, и сбрасывается при смене источника. График одного канала по умолчанию показывает только поддерживающие выбранную гипотезу качественные пики, атомные группы или молекулярные области. Переходы между кандидатом, гипотезой и пиком сохраняют текущий выбор и масштаб графика, но не создают новых предметных сущностей.

Панель выбранного пика различает ближайший по `normalizedDelta` справочный кандидат и фактическое назначение в принятой гипотезе. Связи вычисляются чистой UI-проекцией в `src/features/demo-analysis/model/peak-candidates-ui.ts` по `evidence.memberLineIds` и наблюдению выбранного `peakId`; предметный результат не дополняется состояниями представления. Назначения показываются по существующим неразрешимым спектральным группам. Остальной список визуально объединяет только записи с одинаковыми показываемыми элементом, степенью ионизации, округлённой до отображаемой точности длиной, происхождением длины и средой, сохраняя все стабильные идентификаторы. Компактный вид показывает обязательные назначения, отдельного ближайшего кандидата и до пяти альтернатив; полный локальный список раскрывается с поиском и фильтрами, которые не сохраняются и не запускают пересчёт.

## Локальная разработка

Требуется Node.js 20.9 или новее и pnpm.

```bash
pnpm install
pnpm dev
```

Основные проверки:

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm library:check
pnpm molecular:check
pnpm experimental:check
pnpm verify:identification
```

Полный набор проверок запускается командой:

```bash
pnpm check
```

Изменения предметных алгоритмов, парсинга, моделей сессии и формата отчёта сопровождаются модульными тестами. Production-сборка должна проходить перед публикацией.

## Публикация на Vercel

Репозиторий разворачивается как стандартное Next.js-приложение. Vercel автоматически определяет фреймворк, использует `pnpm install` и запускает `pnpm build`; отдельная конфигурация для базового развёртывания не требуется.

Проект не использует `output: "export"`: статически доступные страницы могут пререндериться автоматически, но серверные возможности Next.js остаются доступными для будущих API, отчётов и интеграций. Конфигурация Cloudflare Wrangler к проекту не относится.
