# Интерпретатор спектра

## Назначение приложения

Приложение — рабочее пространство для интерпретации спектральных данных. Пользователь загружает измерение, проверяет качество исходных данных, подготавливает спектр, находит и проверяет пики, сопоставляет их со спектральными линиями и формирует объяснимое заключение.

Основные продуктовые принципы:

- исходные измерения не изменяются незаметно;
- каждое заключение прослеживается до конкретных пиков и линий справочной библиотеки;
- автоматическое определение является проверяемой гипотезой, а не безусловным результатом;
- отрицательный или неопределённый результат считается полноценным;
- параметры, преобразования, версия библиотеки и пользовательские решения должны сохраняться для воспроизводимости анализа;
- числовая оценка совпадений является эвристикой ранжирования, а не статистически калиброванной вероятностью.
- тип спектра ограничивает только физически допустимые методы интерпретации и никогда не задаёт ожидаемый химический состав.

## Технический стек

Основной стек:

- Next.js 16 с App Router;
- React 19;
- TypeScript 6 в строгом режиме;
- CSS Modules и CSS custom properties для интерфейса и дизайн-токенов;
- pnpm 11;
- Vitest для модульных тестов;
- данные текущего анализа хранятся только в памяти до перезагрузки страницы;
- Vercel как целевая среда публикации.
- Zustand для состояния интерактивного редактора текущей сессии;
- Apache ECharts с модульными импортами для визуализации спектра;
- Lucide React как единый набор интерфейсных иконок;
- Radix Primitives, подключаемые отдельными пакетами, для доступных диалогов, popover, tooltip, tabs и других интерактивных паттернов;
- `clsx` для условной композиции классов CSS Modules;
- Zod для runtime-валидации импортируемых данных и границ будущего API;
- SheetJS CE для чтения XLSX-файлов в браузере;
- TanStack Table для сортировки, фильтрации, выбора и представления таблиц пиков и спектральных линий;
- React Testing Library для тестирования компонентов;
- Playwright для сквозных пользовательских сценариев.
- `tsx` для запуска локальных TypeScript-генераторов данных в разработке.
- AGENTS.md необходимо обновлять при изменении архитектуры, существующих продуктовых решений или технического стека.

Предполагаемые зависимости добавляются только вместе с функциональностью, которая их использует. Radix Primitives подключается по отдельным компонентным пакетам, а ECharts — через модульные импорты, чтобы не включать в клиентский bundle неиспользуемый код.

## Архитектура

Код разделён на слои:

- `src/app` — маршруты Next.js, layout и композиция страниц;
- `src/features` — вертикальные пользовательские сценарии и их UI;
- `src/application` — операции импорта, экспорта и координация предметных сценариев;
- `src/domain` — предметные модели, алгоритмы анализа и контракты хранилищ;
- `src/infrastructure` — адаптеры браузерных API и будущих внешних сервисов;
- `src/fixtures` — демонстрационные и тестовые спектры.

Направление зависимостей идёт от интерфейса и инфраструктуры к предметному ядру. `src/domain` не зависит от React, DOM, Next.js, Vercel или конкретного хранилища. Алгоритмы анализа остаются чистыми функциями, чтобы их можно было выполнять в браузере, Web Worker, серверном маршруте или отдельном пакете.

JSON-, XLSX- и AvaSoft RAW8-парсеры находятся на границе `src/application/import-spectrum`: они валидируют внешние данные до передачи в предметное ядро. RAW8 разбирается локально из `ArrayBuffer` через `DataView`; массивы `dark` и `reference` сохраняются как вспомогательные исходные данные и не применяются автоматически. Исходный порядок точек хранится без изменений; сортируется только отдельная подготовленная копия, и сортировка фиксируется как выполненная операция.

Рабочее пространство хранит исходный импорт, параметры и результат только в памяти; Zustand предназначен для временного состояния редактора. Автосохранение и восстановление удалены: IndexedDB и localStorage не используются, после перезагрузки открывается пустое рабочее пространство. Переходы между разделами сохраняют текущий анализ в общем провайдере. Видимость слоёв спектрального графика и текущий диапазон масштабирования относятся только к представлению: они не входят в предметную модель, не запускают пересчёт и не сохраняются в рабочей сессии. В разделе «Данные» график всегда показывает только неизменённый исходный спектр; переключатели слоёв доступны в аналитических разделах. Диапазон масштабирования сохраняется при обновлении результата одного анализа и сбрасывается при смене источника данных.

Временные выборы редактора хранятся в отдельном Zustand store на экземпляр рабочего пространства. Тяжёлый аналитический конвейер выполняется в Web Worker и получает только структурированное входное состояние; отмена пересчёта завершает текущий worker. Справочные библиотеки не входят в первый клиентский пакет. Worker использует детерминированную атомную проекцию без переходов и библиографии, не участвующих в идентификации; полный NIST-артефакт остаётся каноническим. Страницы используют небольшие проверяемые проекции метаданных библиотек. Таблица пиков построена на TanStack Table и остаётся представлением предметных результатов, не изменяя их.

Предметная модель сессии схемы 4 для формирования отчёта описывает расширяемый тип спектра и параметры коррекции шкалы длины волны. Новые анализы и сессии создаются с `plasma-emission`. Значение `unspecified` остаётся только внутренним legacy-значением для чтения старых данных, не создаётся заново и не показывается в интерфейсе; при загрузке оно, как и отсутствующий тип старой схемы, нормализуется в `plasma-emission` без изменения исходных измерений. Селектор типа остаётся видимым в разделе «Данные» и содержит один вариант «Эмиссия плазмы/разряда», сохраняя возможность расширения списка. Тип не влияет на ожидаемые элементы и разрешает только физически применимые предметные методы. Молекулярный анализ N₂/N₂⁺ для новых анализов выполняется автоматически.

Каждая вкладка имеет собственное рабочее пространство в памяти. Синхронизация между устройствами потребует аутентификации и серверного хранилища.

Встроенная библиотека спектральных линий формируется из ограниченной официальной TSV-выгрузки NIST ASD 5.12. Исходные выгрузки и параметры выборки находятся в `data/nist-asd`, чистые парсер и нормализатор — в `src/application/spectral-library`, детерминированный генератор — в `scripts/build-spectral-library.ts`, готовый версионированный файл — в `src/domain/spectral-library/generated`. Приложение и production-сборка не обращаются к NIST по сети. Команды `pnpm library:build` и `pnpm library:check` соответственно обновляют и проверяют локальный результат.

Молекулярная библиотека является отдельным локальным набором и не смешивается с атомными линиями. Первая версия содержит N₂ C³Πᵤ→B³Πg и N₂⁺ B²Σᵤ⁺→X²Σg⁺ из Moose/MassiveOES. Исходная версия, лицензия MIT, публикации, SHA-256 оригинальных баз и ограниченной выгрузки зафиксированы в `data/molecular-spectra`; импорт и генерация выполняются скриптами `scripts/import-moose-molecular-source.ts` и `scripts/build-molecular-library.ts`, готовый файл находится в `src/domain/molecular-spectrum/generated`. Production не обращается к внешнему источнику.

Каждая справочная линия является отдельной предметной сущностью со стабильным идентификатором, элементом, степенью ионизации, наблюдаемой и Ritz-длиной волны, явно выбранной предпочтительной длиной и средой, исходной относительной интенсивностью, доступными характеристиками перехода, ссылками и версией источника. Наблюдаемая длина предпочтительна; Ritz используется только при её отсутствии. Отсутствующие характеристики не заполняются предположениями. Манифест фиксирует источник, версию NIST, DOI, дату получения, параметры выборки, число строк и SHA-256 нормализованных записей. Завершённый анализ хранит использованную версию библиотеки, параметры, исходный набор данных и результат.

Единый предметный конвейер принимает один или несколько спектрометрических каналов. Каждый канал имеет стабильный идентификатор, собственные исходные данные, параметры, диапазон, кривые базовой линии, локального шума и порога, подготовленный спектр, пики и воспроизводимую FWHM-оценку фактического разрешения. Если один импортированный массив содержит разрывы шкалы или длинные повторяющиеся минимумы-маски, рабочая копия автоматически разделяется на непрерывные детекторные диапазоны; маски не считаются измеренным нулевым сигналом, а загруженный исходный массив не изменяется. Разные файлы не объединяются автоматически. Подготовка и поиск пиков независимы по каналам, гипотезы строятся по совокупности каналов.

Подготовка использует один воспроизводимый метод: сглаживание Савицкого—Голея, робастную кривую базовой линии AsLS на фактической сетке длин волн, локальный MAD первых разностей остаточного сигнала и выбранную нормализацию. Пик хранит канал, исходный индекс, измеренную и уточнённую координаты, неопределённость положения, исходную и подготовленную интенсивность, выраженность, SNR и физическую ширину. Качественные пики уточняются квадратичным локальным профилем только в подготовленной копии. Поиск учитывает минимальный SNR, выраженность, диапазон ширины и расстояние. Локальный порог является кривой. Алгоритмы и обоснование параметров документированы в `docs/analysis-pipeline.md` и `docs/identification-quality-profile.md`.

Молекулярные системы сопоставляются с формой нескольких характерных участков, а не с набором локальных максимумов. Эталон переносится на фактическую сетку и сворачивается до оценённого разрешения канала; подбор использует локальную базовую линию, шум и одно малое общее смещение длины волны. Одиночный участок, отсутствие ключевого участка или результат, не отделившийся от смещённых отрицательных контролей, отклоняется. Числовое качество формы — только эвристика ранжирования и не интерпретируется как вероятность, концентрация или температура плазмы.

Атомные N, молекулярные N₂ и N₂⁺ остаются разными гипотезами и объединяются только в пользовательском объяснении элемента «Азот». Пики, перекрывающиеся с молекулярной полосой, сохраняются в модели, но атомные и молекулярные индексы не складываются: один участок сигнала не учитывается дважды как независимое доказательство.

Фиксированный допуск сопоставления не используется. Каждый кандидат получает адаптивный допуск из шага сетки, оценённого разрешения, ширины и SNR пика, неопределённости уточнения положения, доступной неопределённости справочной линии и неопределённости калибровки. Все компоненты сохраняются в результате. Минимальное расстояние поиска пиков ограничивается локальным шагом сетки, поэтому один числовой параметр не подавляет разрешаемые УФ-линии. Для идентификации соседние линии одного элемента и степени ионизации объединяются в спектральные группы по лучшему доступному разрешению пригодных каналов; один низкоразрешающий канал не скрывает разделение, которое реально наблюдается другим. Гипотезы используют точное взаимно-однозначное сопоставление пиков и групп внутри элемента и канала с явной возможностью оставить слабое пограничное совпадение неназначенным. Неразрешимый мультиплет является одним независимым свидетельством, но все его линии и наблюдения сохраняются для прослеживаемости и многоканальной поддержки.

До идентификации канал оценивается отдельно по покрытию, сигналу, разрешению и калибровке. Диагностика успешно скорректированной базовой линии, расчётного разрешения и отсутствующей паспортной неопределённости не понижает пригодность; предупреждения относятся только к свойствам сигнала или покрытия, способным повлиять на интерпретацию. Без известной разрядности повторение предельного значения не называется насыщением. Критический канал исключается, но многоканальное измерение остаётся пригодным, пока доступен хотя бы один некритический канал. Автоматическая коррекция допускает лишь общее смещение при нескольких сильных однозначных опорах, разнесённых по диапазону, и обязана улучшить независимую проверочную часть. Она применяется только к подготовленным копиям, сохраняет метод, величину, неопределённость и опоры и может быть отключена. Все константы собраны в версионированном профиле `src/domain/spectrum/quality-profile.ts`.

Характерные признаки выбираются отдельно для элемента и степени ионизации после группировки по разрешению: только покрываемые наблюдаемые линии с числовой однозначной относительной интенсивностью, до десяти наиболее интенсивных спектральных групп. Соседние члены найденного мультиплета не считаются отсутствующими. Относительная интенсивность сравнивается только внутри элемента и степени ионизации и не является вероятностью. Качество наблюдения учитывает SNR, выраженность, ширину, отклонение, многоканальную поддержку и неоднозначность пика; числовые индексы являются эвристиками порядка, не вероятностями. Атомная гипотеза обязана иметь не менее трёх качественных групп, ключевой и достаточно специфичный признак, согласованное общее смещение внутри каналов и превзойти все детерминированные циклически смещённые контроли; очень точное многолинейное созвездие может пройти консервативный контроль при четырёх специфичных группах либо при трёх полностью специфичных группах с сильным признаком, хотя бы одной ключевой группе и малой доле равноценных контролей. Отклонённая гипотеза никогда автоматически не переносится в основной список. Слабые, нехарактерные, единичные, неоднозначные и не отделившиеся от контролей гипотезы хранятся с причинами. Идентификатор пика привязан к каналу и позиции точки в неизменённом исходном наборе, в том числе после автоматического выделения рабочих детекторных диапазонов, поэтому UI может сохранять выбор при пересчёте, пока эта точка остаётся пиком. Выбранный пик относится только к состоянию интерфейса, не входит в предметный результат и не сохраняется в рабочей сессии; при смене источника выбор всегда сбрасывается.

Верхнеуровневая навигация состоит из разделов «Данные», «Обработка», «Анализ» и «Библиотека». Основной путь — загрузить или заменить измерение в «Данных», дождаться автоматического пересчёта, изучить спектр и таблицу пиков в «Анализе», при необходимости открыть интерпретацию. Видимый селектор физического типа не добавляет обязательного шага перед импортом. Отдельного запуска подготовки, поиска пиков и идентификации нет: после загрузки и изменения значимых параметров единый конвейер пересчитывается автоматически. Во время пересчёта предыдущий результат остаётся резервным валидным состоянием, но визуально скрывается и не выдаётся за актуальный. «Библиотека» является самостоятельным справочным разделом; незавершённого раздела результата и экспорта в основной навигации нет.

Раздел «Анализ» ориентирован на профессионального лаборанта. Основной результат — подготовленный спектр и таблица характеристик пиков. Режим «Спектр и пики» открывается при новом импорте: график показывает подготовленный сигнал и найденные пики, доступны исходный сигнал, базовая линия и порог. Таблица содержит координату, подготовленную интенсивность, ширину на половине выраженности, SNR и фактические атомные назначения принятых гипотез. Ближайший справочный кандидат остаётся отдельным понятием в инспекторе. На широком экране инспектор находится справа. Интерпретация доступна под таблицей и в дополнительном режиме с доказательствами; отсутствие принятой гипотезы не обесценивает спектр и пики. В режиме «Интерпретация» гипотезы расположены слева; на малых экранах выбор доступен в карточке вывода. Выбранные гипотеза, канал, пик и режим являются UI-состоянием, сохраняются при пересчёте существующих сущностей и сбрасываются при смене источника. Масштаб графика сохраняется при переходах внутри анализа.

Из таблицы доступны CSV пиков, CSV подготовленного спектра выбранного канала и JSON полного результата со всеми каналами, исходными измерениями, параметрами, поправками шкалы и версиями библиотек. CSV сохраняет числовую точность модели, определение ширины указано в заголовке. JSON имеет exportVersion 1; не-конечные числа кодируются строками Infinity, -Infinity и NaN. Экспорт не означает автосохранения.

Необязательный processing.analysisRange задаёт границы анализа в нм независимо от масштаба графика. Ограничение применяется к рабочим детекторным диапазонам до подготовки, сохраняет исходный импорт и индексы точек. Участки с менее чем тремя точками исключаются; пустое покрытие даёт ошибку. Параметр включается в полный экспорт. Ползунки применяют значение после завершения изменения и допускают точный ввод. Оценка шума, дополнительные ограничения пиков и экспертные пороги интерпретации имеют отдельные раскрываемые блоки. Порог выраженности задаётся в шкале подготовленного сигнала, допускает значения больше единицы.

Панель выбранного пика различает ближайший по `normalizedDelta` справочный кандидат и фактическое назначение в принятой гипотезе. Связи вычисляются чистой UI-проекцией в `src/features/demo-analysis/model/peak-candidates-ui.ts` по `evidence.memberLineIds` и наблюдению выбранного `peakId`; предметный результат не дополняется состояниями представления. Назначения показываются по существующим неразрешимым спектральным группам. Остальной список визуально объединяет только записи с одинаковыми показываемыми элементом, степенью ионизации, округлённой до отображаемой точности длиной, происхождением длины и средой, сохраняя все стабильные идентификаторы. Компактный вид показывает обязательные назначения, отдельного ближайшего кандидата и до двух альтернатив; полный локальный список раскрывается с поиском и фильтрами, которые не сохраняются и не запускают пересчёт.

## Локальная разработка

Требуется Node.js 20.9 или новее и pnpm.

```bash
pnpm install
pnpm dev
```

Основные проверки:

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
pnpm library:check
pnpm molecular:check
pnpm experimental:check
pnpm verify:identification
```

Полный набор проверок запускается командой:

```bash
pnpm check
```

После production-сборки `pnpm bundle:check` ограничивает первый несжатый клиентский пакет каждого маршрута 1,25 МБ. Детали и правила для горячих участков описаны в `docs/performance.md`.

Изменения предметных алгоритмов, парсинга, моделей сессии и формата отчёта сопровождаются модульными тестами. Production-сборка должна проходить перед публикацией.

## Публикация на Vercel

Репозиторий разворачивается как стандартное Next.js-приложение. Vercel автоматически определяет фреймворк, использует `pnpm install` и запускает `pnpm build`; отдельная конфигурация для базового развёртывания не требуется.

Проект не использует `output: "export"`: статически доступные страницы могут пререндериться автоматически, но серверные возможности Next.js остаются доступными для будущих API, отчётов и интеграций. Конфигурация Cloudflare Wrangler к проекту не относится.

Все существующие параметры анализа находятся в «Обработке» в подразделах «Подготовка спектра», «Поиск пиков» и «Определение состава», с переключаемыми вкладками: одновременно видны параметры только одного подраздела. Прямая ссылка #peak-settings открывает вкладку поиска пиков. Переходы между «Анализом» и «Обработкой» выполняются через основную навигацию без дополнительных кнопок. Вкладки компактны и адаптируются к ширине панели; на сенсорных экранах сохраняется увеличенная область нажатия. Боковая панель пиков сразу показывает инспектор или приглашение выбрать пик, без переключателя на параметры. Подсказки настроек объясняют влияние параметра и компромиссы понятным языком.


Определение состава использует профиль `composition-v1` в `src/domain/spectrum/composition-settings.ts`. Режимы «Строгий», «Стандартный» и «Чувствительный» задают требования к качеству и количеству атомных групп и областей молекулярных полос; ручное изменение включает «Пользовательский». Стандартный режим сохраняет прежние требования. Минимум три атомные группы, ключевой специфичный признак, согласованность смещения и контроль случайных совпадений сохраняются. Чувствительный режим допускает менее качественные подтверждения и отсутствие сильной группы при выполнении обязательных проверок; принятые таким образом результаты отмечены. Отклонённые результаты доступны как возможные совпадения, включая молекулы.

Фильтр «Все / Исключить / Только» ограничивает гипотезы, а не подготовку, поиск пиков или набор конкурирующих линий. Исключённые элементы учитываются в неоднозначности и контролях, поэтому фильтрация не усиливает оставшиеся гипотезы. Пустой список «Только» отключает определение состава; выбор N управляет атомным N и обеими молекулярными системами. Ограничение и режим видны рядом с составом. Тип спектра не задаёт фильтр.

Браузерного адаптера сохранения сессий нет. Предметная модель сессии и миграции схем остаются для формирования отчёта; они не подключены к постоянному хранилищу.


Панель «Обработка» использует единую шкалу: на широких экранах ширина 360 px, внутренние отступы 20 px, поля и вкладки высотой 36 px, расстояния между параметрами 12 px и группами 20 px. На сенсорных экранах основные поля и вкладки имеют высоту от 44 px. Точный ввод расположен рядом с подписью ползунка, раскрытия представлены компактными строками. На широких экранах панель прокручивается независимо от графика. Порядок групп: диапазон, сглаживание, базовая линия, интенсивность, шкала длины волны. Результат коррекции показан для выбранного канала; остальные каналы доступны отдельно. Приблизительный физический размер окна сглаживания оценивается по сетке выбранного канала с учётом расстояний между точками.

Начальное представление графика зависит от вкладки обработки: подготовка — исходный сигнал, фон и подготовленный спектр; поиск пиков — подготовленный спектр, порог и пики; состав — подготовленный спектр и подтверждения выбранной гипотезы. Изменения видимости слоёв сохраняются независимо для вкладок в памяти компонента без предметного пересчёта. Смена вкладки не сбрасывает масштаб графика. Крупные и малые значения интенсивности на оси отображаются в научной записи без изменения исходных чисел.

Раскрытия настроек показывают краткие актуальные значения в закрытой строке (окно шума, выраженность и расстояние, профиль подтверждений); раскрытие «Другие каналы» показывает число дополнительных каналов. Редакторы параметров и результаты расчёта имеют разные подписи и общий компактный формат без вложенных карточек. После ошибки изменения раскрытие остаётся открытым до успешной проверки; успешный расчёт снимает ограничение закрытия. Сводки допускают перенос значений на вторую строку. Сглаживание и нормализация не дублируются отдельными заголовками групп.


Инспектор «Анализа» на широких экранах является независимой правой панелью шириной 360 px с собственной прокруткой и закреплённым заголовком. Содержит вкладки «Параметры» и «Соответствия»; выбор вкладки сохраняется при смене пика и пересчёте и сбрасывается при новом импорте. Координата показана один раз в заголовке, там же доступны соседние пики выбранного канала по длине волны. Параметры измерения предшествуют интерпретации: интенсивности с единицами, ширина на половине выраженности, SNR и неопределённость положения; детали уточнения и обнаружения раскрываются отдельно. Выбор назначения в таблице и переход из доказательств открывают «Соответствия». Автопрокрутка выбранной строки ограничена контейнером таблицы, сохраняется при сортировке и не изменяет масштаб графика.

Соответствия представлены компактными раскрываемыми строками с длиной и отклонением. Назначения принятых гипотез, ближайший кандидат и альтернативы остаются различимы. Общая среда и происхождение длины показаны одной подписью, исключения — в строке. Расчёт допуска раскрывается при выбранном соответствии; факт ограничения допуска показывается только при его достижении. Полная справочная запись (все члены группы, уровни, переходы, библиография, источник и идентификаторы) открывается в доступном модальном окне Radix Dialog; каноническая библиотека загружается динамически только при открытии окна. Отсутствующие характеристики не заменяются предположениями. Radix Dialog подключён отдельным пакетом @radix-ui/react-dialog; обеспечивает фокус, Escape и возврат к исходному элементу.

На экранах до 820 px инспектор открывается как отдельная модальная боковая панель после выбора пика. Закрытие панели сохраняет выбор и вкладку; повторное открытие доступно отдельной кнопкой. Полная справочная запись открывается поверх панели и закрывается с возвратом фокуса. Основной режим содержит компактную сводку интерпретации и переход к доказательствам; ограничения области поиска и нестандартный режим отбора остаются видимыми. Таблица пиков имеет компактные строки высотой около 40 px.

В «Анализе» обе боковые панели на широких экранах прокручиваются независимо от рабочей области. Наведение или фокус на строке пика временно выделяет его маркер на графике, не меняя выбранный пик, масштаб и предметный результат. Отклонённые молекулярные гипотезы показываются как диагностические проверки с отдельными причинами, а не как возможные совпадения. Повтор параметров обработки и текстов преобразований убран из основной страницы; полные параметры, преобразования и версии источников доступны в JSON-экспорте.

Неподтверждённые молекулярные системы не показываются в основном выводе: их причины доступны только в «Доказательствах и показателях», в подразделе «Проверка молекулярных систем», и в JSON. Экспорт оформлен кнопкой с доступным меню действий на Radix Dropdown Menu; CSV относится к выбранному каналу, JSON содержит полный анализ.

Общие UI-примитивы находятся в `src/components/ui`. Все кнопки приложения используют `Button` (`button.tsx` и `button.module.css`): варианты primary, secondary, ghost и text; размеры default (36 px), compact (30 px), icon (36 px) и hint (24 px), с областью нажатия минимум 44 px на сенсорных экранах. Цвета, рамки, отступы, focus/hover/disabled и выбранные состояния определяются централизованно. Локальные CSS Modules задают только размещение и предметную композицию. `asChild` через Radix Slot сохраняет семантику ссылок и совместимость с Radix Trigger/Close без вложенных интерактивных элементов.

Все селекторы интерфейса используют общий `Select`/`SelectItem` из `src/components/ui/select.tsx` на Radix Select вместо системного `<select>`. Триггер использует Button; всплывающая поверхность и строки списка разделяют стили `menu-surface.module.css` с меню экспорта. Сохраняются подписи, клавиатурный выбор, фокус и прежние значения параметров.

«Интерпретация» отделяет компактную сводку всего измерения от выбранного результата с явным статусом. На широких экранах выбор находится только в независимой панели состава (360 px, 320 px при ширине до 1280 px); на мобильных общий селектор включает и неподтверждённые атомные результаты и отражает фактический выбор. Карточки списка используют отдельный ResultChoice с общими размерами и выравниванием влево. После графика сразу видна таблица доказательств: по умолчанию качественные характерные группы, переключатель открывает все сопоставления; ключевые группы идут первыми. Числовой индекс и происхождение линий раскрываются только у одной выбранной строки и не меняют выбранный пик. Ненайденные признаки перечисляются один раз по степеням ионизации. Проверка случайных совпадений и согласованность шкалы показывают фактические предметные флаги; подробные числовые показатели находятся отдельно в «Подробностях расчёта». Молекулярные проверки всего измерения расположены отдельно от выбранного элемента. Переработка меняет только UI-проекции, не критерии принятия гипотез.

Раскрытие списка «Другие совпадения» независимо от выбранной гипотезы: список открыт по умолчанию, сворачивание и раскрытие не меняют выбор, сортировка всегда видна внутри раскрытого списка. Подробности строки доказательств содержат компактные параметры, а полный состав справочных линий и стабильные идентификаторы открываются в общем модальном окне ReferenceRecordDialog с возвратом фокуса. Пояснения к эвристическому индексу, контролям и молекулярной проверке доступны в тултипах; причины непринятия остаются видимыми.

В разделе «Данные» диапазон, число точек и средний шаг находятся в подписи исходного графика. Компактный блок измерения содержит файл, формат, источник, единицы и селектор типа. Таблица «Каналы и характеристики» открыто показывает все рабочие диапазоны; автоматически выделенные участки различаются номером в UI без изменения предметного результата. Диагностика участка и коррекция шкалы доступны в его диалоге. Метаданные прибора и статистика интенсивности находятся в диалоге импорта. Число пиков и оценка достаточности признаков не дублируются в основном представлении «Данных».

В «Анализе» обе независимые панели закреплены справа с одинаковой шириной 360 px на экранах шире 820 px: инспектор пика в режиме спектра и список состава в интерпретации. Заголовок и переключатель режимов образуют закреплённую шапку рабочей области. На узких экранах сохраняются выбор состава в содержимом и выезжающий инспектор пика.

Графики масштабируются только по X: в полном масштабе перетаскивание ЛКМ выделяет участок, после увеличения перемещает спектр; кнопка выделения позволяет повторно выбрать участок. Доступны обзорный ползунок и ввод границ видимого диапазона. Колесо прокручивает страницу; двойной щелчок и кнопка сбрасывают масштаб. Ввод диапазона меняет только представление и не заменяет processing.analysisRange. Автоматически выделенные диапазоны одного импортированного канала в селекторе обозначаются как участки с отдельными номерами, а не как подтверждённые физические каналы прибора. Управление шкалой Y пока не добавляется. Выбранный пик отмечается кольцом и вертикальным ориентиром; справочные отметки сохраняются даже при скрытии тесно расположенных подписей.

Повторяющиеся элементы интерфейса находятся в `src/components/ui`: Input, NumberField, Checkbox, Switch, RangeInput, FieldLabel, CardHeader, MetricList, StatusBadge, Disclosure, DialogSurface и DialogHeader. Их внешний вид не зависит от системных спиннеров, маркеров и ползунков; настоящие HTML-контролы сохраняют клавиатурную семантику. Окна используют Radix для фокуса и закрытия. Типографика и размеры задаются токенами, а CSS страниц отвечает за предметную компоновку. Правила и инвентаризация описаны в `docs/ui-components.md`. NumberField сохраняет отложенное применение по blur/Enter и отмену по Escape; кнопки шага применяют изменение явно.
