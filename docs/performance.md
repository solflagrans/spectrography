# Производительность приложения

## Клиентская загрузка

Полные атомная и молекулярная библиотеки не входят в JavaScript, необходимый для первого открытия рабочего пространства. Интерфейс использует компактные проекции метаданных. Фоновый анализатор получает отдельную атомную проекцию без переходов и библиографии, которые не участвуют в расчёте; полный NIST-артефакт остаётся источником для проверки и прослеживаемости.

После production-сборки команда `pnpm bundle:check` проверяет статистику Next.js. Лимит для каждого маршрута — 1,25 МБ несжатого JavaScript при первом открытии. Фоновый worker в этот лимит не входит: он загружается только при запуске анализа.

## Расчёт

Единый аналитический конвейер выполняется в Web Worker. При изменении параметров предыдущий незавершённый запрос отменяется, worker перезапускается, а последний корректный результат остаётся доступен до завершения нового расчёта. В окружениях без Worker используется асинхронно загружаемый совместимый исполнитель.

Для горячих участков действуют следующие ограничения:

- поиск ближайших точек графика использует двоичный поиск на отсортированной шкале;
- оценка молекулярных областей обрабатывает только нужный диапазон канала;
- медиана локального шума вычисляется выбором порядковой статистики без полной сортировки;
- подавление соседних пиков проверяет только потенциально конфликтующий диапазон.

Изменения алгоритмов должны сопровождаться сравнением результатов на синтетической матрице и командой `pnpm check`.
